# Навантажувальне тестування

## Сценарій

Тестування виконується скриптом `loadtest/script.js` за допомогою `k6`. За одну ітерацію кожен віртуальний користувач здійснює 1 операцію запису та 9 операцій читання:

1. `POST /appointments/` — реєстрація нового запису на прийом (із передачею JWT-токена);
2. `GET /appointments/` — отримання повного списку прийомів (3 запити за ітерацію);
3. `GET /appointments/{id}` — перевірка створеного запису за ідентифікатором (2 запити за ітерацію);
4. `GET /doctors/{id}` — читання картки лікаря (2 запити за ітерацію);
5. `GET /patients/{id}` — читання картки пацієнта (1 запит за ітерацію);
6. `GET /services/` — отримання переліку доступних послуг (1 запит за ітерацію).

Після кожного циклу виконується затримка `0,5 с`. На етапі ініціалізації (`setup()`) скрипт авторизується через `POST /auth/login` і створює тестові записи лікаря та пацієнта, щоб забезпечити коректні зовнішні ключі для подальших `POST`-запитів.

## Параметри

| Фаза | Тривалість | Віртуальні користувачі |
|---|---|---|
| Наростання | 3 хв | 0 → 40 |
| Стале навантаження | 5 хв | 40 |
| Спад | 2 хв | 40 → 0 |

`N = 40`: за такої кількості одночасних користувачів навантаження на процесор перевищує цільовий поріг `60%`, що запускає горизонтальне масштабування сервісу.

## Команда запуску

```powershell
k6 run --summary-trend-stats="avg,min,med,max,p(90),p(95),p(99)" -e BASE_URL=[http://lab-alb-303278754.eu-north-1.elb.amazonaws.com](http://lab-alb-303278754.eu-north-1.elb.amazonaws.com) -e VUS=40 loadtest/script.js
```

| Показник | Значення |
|---|---|
| Усього запитів | 12 503 |
| Помилок | 0 (0%) |
| Запитів за секунду | 20,77 |
| Латентність p50 | 1,14 с |
| Латентність p95 | 3,42 с |
| Латентність p99 | 11,08 с |

Під час базового тесту без кешування пікова латентність p95 на балансувальнику сягала 8,6 с, а кількість контейнерів ECS зросла з 1 до 4 (див. [AUTOSCALING.md](AUTOSCALING.md) та [CACHE.md](CACHE.md)).
