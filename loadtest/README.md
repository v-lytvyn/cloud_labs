# Навантажувальний тест (`k6`)

Директорія містить сценарій навантажувального тестування REST API на базі інструменту **Grafana k6** (`loadtest/script.js`).

## Вимоги

* Встановлений [k6](https://k6.io/docs/get-started/installation/) наприклад, через `winget install k6` у Windows.
* Запущений екземпляр API локально через Docker Compose або розгорнутий в AWS ECS за балансувальником ALB.

---

## Сценарій тестування (`script.js`)

### 1. Підготовка даних (`setup`)
Перед початком генерації навантаження скрипт одноразово виконує:
1. Авторизацію через `POST /auth/login` та отримання JWT-токена.
2. Створення тестового лікаря (`POST /doctors/`) і пацієнта (`POST /patients/`), щоб забезпечити валідні зовнішні ключі (`doctor_id`, `patient_id`) для записів на прийом.

### 2. Робочий цикл віртуального користувача (`default`)
У кожній ітерації користувач виконує **10 HTTP-запитів** у співвідношенні **1 запис : 9 читань**, після чого робить паузу `0,5 с`:

| Тип | Метод та ендпоінт | Кількість за цикл | Призначення |
|---|---|---|---|
| Запис | `POST /appointments/` | 1 | Створення нового запису на прийом (з JWT) |
| Читання | `GET /appointments/` | 3 | Отримання повного списку прийомів (перевірка кешу Redis) |
| Читання | `GET /appointments/{id}` | 2 | Отримання щойно створеного запису за ID |
| Читання | `GET /doctors/{id}` | 2 | Отримання профілю лікаря |
| Читання | `GET /patients/{id}` | 1 | Отримання профілю пацієнта |
| Читання | `GET /services/` | 1 | Отримання переліку медичних послуг |

## Профіль навантаження та змінні середовища

Стандартний прогін триває **10 хвилин** і складається з трьох етапів:

| Фаза | Тривалість | Віртуальні користувачі (`VUS`) |
|---|---|---|
| Наростання (`ramp-up`) | `3m` | `0 → N` |
| Стале навантаження (`steady state`) | `5m` | `N` |
| Спад (`ramp-down`) | `2m` | `N → 0` |

### Параметри запуску (`-e`)
* `BASE_URL` — адреса API без слеша в кінці.
* `VUS` — пікова кількість віртуальних користувачів на етапі сталого навантаження (за замовчуванням `40`).

### Критерій успішності (`thresholds`)
* `http_req_failed: ['rate<0.05']` — частка невдалих запитів не повинна перевищувати **5%**.

### 1. Швидка перевірка працездатності (5 секунд, 1 користувач)
Використовується перед основним прогоном для перевірки доступності ендпоінтів і авторизації:
```powershell
k6 run -u 1 -d 5s -e BASE_URL=ALB_URL loadtest/script.js
